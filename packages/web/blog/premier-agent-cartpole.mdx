Un chariot, un mât et deux actions : pousser à gauche ou pousser à droite. CartPole permet de découvrir l’apprentissage par renforcement avec un objectif visible : garder le mât debout aussi longtemps que possible.

Dans ce tutoriel, nous allons lancer la démo Ignition, entraîner un agent DQN puis passer en inférence. Les captures viennent d’une exécution réelle dans Chromium sur le VPS. Elles montrent les premières étapes du parcours, sans supposer que l’agent a déjà résolu le problème.

## 1. Lancer la démo

Vous avez besoin de **Node.js 20 ou 22**, de Git et de **pnpm 10.8.0**. Nous utilisons le code du dépôt pour que la démo et les exemples correspondent à la même version.

```bash
 git clone https://github.com/IgnitionAI/ignition.git
 cd ignition
 corepack enable
 pnpm install --frozen-lockfile
 pnpm --filter demo-cartpole dev --host 127.0.0.1 --port 5173
```

Ouvrez [http://localhost:5173](http://localhost:5173). Vous pouvez aussi [essayer la démo hébergée](/demos/cartpole/). Depuis un serveur distant, utilisez un tunnel SSH vers le port 5173 ; l’adresse localhost de votre ordinateur ne désigne pas le VPS.

## 2. Comprendre ce que voit l’agent

L’environnement fournit quatre nombres : la position du chariot, sa vitesse, l’angle du mât et sa vitesse angulaire. L’agent choisit ensuite l’une des deux actions. Il ne lit pas les pixels du canvas : l’image sert à nous montrer la simulation.

Dans cette implémentation, un épisode se termine lorsque le chariot dépasse ±2,4 mètres, lorsque le mât dépasse ±12 degrés ou après 500 transitions. Chaque transition non terminale rapporte une récompense de 1 ; la transition terminale rapporte 0.

Le graphique intitulé **Steps balanced** compte les transitions de chaque épisode, y compris la dernière. Il ne représente donc pas exactement la somme des récompenses. Cette différence d’une unité compte lorsqu’on compare des résultats.

`IgnitionEnvTFJS` relie l’environnement aux agents TensorFlow.js. `train('dqn')` crée le DQN et lance la boucle automatique. Le runner déduit les dimensions à partir des observations et des actions ; il fournit également les paramètres par défaut.

L’exemple expose les commandes nécessaires à une interface. `session.infer()` applique la politique courante sans poursuivre l’apprentissage. `session.resume()` reprend l’entraînement du même agent. `session.stop()` annule les prochaines itérations automatiques ; une transition déjà commencée peut encore finir.

Pour essayer ce module pendant que Vite tourne, ouvrez la console du navigateur :

```js
const { createCartPoleSession } = await import('/examples/first-agent.ts');
const session = createCartPoleSession();
// Plus tard :
session.infer();
session.stop();
```

Ce module crée une session indépendante : il ne la branche pas au canvas de la démo. Pour le parcours visuel, utilisez les boutons de la page. Le fichier [App.tsx](https://github.com/IgnitionAI/ignition/blob/main/packages/demo-cartpole/src/App.tsx) montre comment synchroniser l’état physique et enregistrer les épisodes dans une interface React.

## 4. Observer l’entraînement

Gardez **DQN** sélectionné et cliquez sur **Train**. Le cadre devient vert et les épisodes alimentent le graphique. Au départ, l’agent explore : une chute rapide fait partie des données qui serviront à apprendre.

![La démo pendant l’entraînement DQN : cadre vert, indicateur TRAINING et courbe des longueurs d’épisode.](/images/blog/cartpole/training.png)

*Capture après une minute d’entraînement avec les réglages par défaut.*

Ne jugez pas l’agent sur un seul épisode. Comparez plusieurs épisodes successifs et, pour une évaluation sérieuse, plusieurs entraînements indépendants. Les états initiaux, l’exploration et les poids du réseau comportent de l’aléatoire : deux exécutions peuvent produire des trajectoires différentes.

La boucle utilise par défaut un délai de 50 ms entre les ticks, auxquels s’ajoute le temps de calcul. Une minute de temps réel n’équivaut donc pas à un nombre garanti de transitions, ni à une garantie de convergence.

## 5. Passer en inférence

Pendant l’entraînement, cliquez sur **Inference**. Le cadre devient bleu. L’agent choisit alors ses actions avec la politique courante, sans mise à jour des poids. Le runner conserve la continuité de la simulation lors de ce changement de mode.

![La même session passée en inférence : cadre bleu et indicateur INFERENCE.](/images/blog/cartpole/inference.png)

*La couleur confirme le changement de mode, pas la qualité de la politique.*

La démo continue à enregistrer les longueurs des épisodes en inférence dans le même graphique. Pour mesurer une performance, relevez séparément les épisodes d’évaluation : ne confondez pas les points d’entraînement et les points d’inférence.

**Train** reprend l’apprentissage ; **Stop** arrête la boucle. **Reset** remet la démo à zéro et abandonne l’agent courant. Ne cliquez donc pas sur Reset pour simplement faire une pause.

## Ce que nous avons vérifié

Pour préparer cet article, nous avons ouvert la démo locale, lancé DQN pendant une minute, basculé en inférence puis arrêté la session. Les trois images montrent cette même exécution. Nous avons aussi importé le module `first-agent.ts` dans le navigateur et exécuté une transition d’entraînement, une transition d’inférence et les commandes de changement de mode.

Cette vérification démontre que le parcours et l’exemple fonctionnent. Elle ne démontre pas que CartPole est résolu ou qu’un score donné sera reproduit sur votre machine.

Pour continuer, consultez [le fonctionnement du DQN](/docs/algorithms/dqn), [le rôle du runner](/docs/how-it-works/core) et [le tutoriel sur les observations CartPole](/docs/tutorials/cartpole-observations). Vous pouvez ensuite modifier les observations ou comparer les agents, en conservant un protocole d’évaluation identique.
